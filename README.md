# ระบบยืม-คืนกายอุปกรณ์การแพทย์

เว็บแอปสำหรับศูนย์ยืม-คืนกายอุปกรณ์การแพทย์ ครอบคลุมการลงทะเบียนผู้ยืม การยืม-คืน คำขอยืมจากผู้ใช้ทั่วไป การนับสต็อก และ audit log

**การจัดเก็บข้อมูล**: เลือกได้ 2 แบบ ระบบตรวจให้อัตโนมัติจากค่าใน `.env` ไม่ต้องแก้โค้ด
- **ไฟล์ JSON local** (ในโฟลเดอร์ `data/`) — ค่าเริ่มต้น ใช้ได้ทันทีโดยไม่ต้องตั้งค่าอะไรเพิ่ม
- **Google Sheets** — ตั้งค่า `GOOGLE_SHEET_ID` + service account ใน `.env` แล้วทุกข้อมูล (ผู้ยืม/อุปกรณ์/รายการยืม-คืน/คำขอ/ผู้ใช้/audit log) จะอ่าน-เขียนลง Google Sheet โดยตรง เปิดดู/แก้ไข/export เป็น Excel ได้จากสเปรดชีตเลย — ดูวิธีตั้งค่าที่หัวข้อ [เชื่อมต่อ Google Sheets](#เชื่อมต่อ-google-sheets) ด้านล่าง

รูปภาพ (บัตรประชาชน/อาการป่วย) เก็บในโฟลเดอร์ `uploads/` บนเครื่อง server เองเสมอ ไม่ว่าจะเลือกฐานข้อมูลแบบไหน (Google Sheets ไม่เหมาะกับการเก็บไฟล์รูปภาพจำนวนมาก)

## เริ่มต้นใช้งาน

```bash
npm install
cp .env.example .env   # แล้วแก้ค่าตามต้องการ (ไม่บังคับสำหรับใช้งานแบบไฟล์ local)
npm run seed     # สร้างผู้ใช้เริ่มต้น + อุปกรณ์ตัวอย่าง (รันครั้งเดียว หรือรันซ้ำได้อย่างปลอดภัย)
npm start        # เปิดเซิร์ฟเวอร์ที่ http://localhost:3000
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:3000` สำหรับหน้าแรก (สาธารณะ), `http://localhost:3000/request.html` สำหรับฟอร์มคำขอยืม (ไม่ต้อง login) หรือ `http://localhost:3000/staff.html` สำหรับหน้าเจ้าหน้าที่ (ต้อง login)

**บัญชีเริ่มต้น** (เปลี่ยนรหัสผ่านทันทีก่อนใช้งานจริง — ดูหัวข้อ "การจัดการผู้ใช้" ด้านล่าง):
- แอดมิน: `admin` / `admin1234`
- เจ้าหน้าที่: `staff` / `staff1234`

ตั้งค่ารหัสผ่านตอน seed เองได้ผ่าน `.env` — คัดลอก `.env.example` เป็น `.env` แล้วแก้ `SEED_ADMIN_PASSWORD` / `SEED_STAFF_PASSWORD` ก่อนรัน `npm run seed`

## เชื่อมต่อ Google Sheets

ค่าเริ่มต้นของระบบใช้ไฟล์ JSON local ถ้าต้องการให้ข้อมูลทั้งหมดไปอยู่ใน Google Sheets แทน (เปิดดู/แก้ไข/แชร์ให้คนอื่นดูสถานะสต็อกได้ง่าย, export เป็น Excel ได้ทันที) ทำตามขั้นตอนนี้ครั้งเดียว:

### ขั้นตอนที่ 1: สร้าง Google Sheet เปล่า

1. ไปที่ [sheets.google.com](https://sheets.google.com) → สร้างสเปรดชีตใหม่ (ตั้งชื่ออะไรก็ได้ เช่น "ฐานข้อมูลศูนย์ยืมกายอุปกรณ์")
2. คัดลอก **Sheet ID** จาก URL — คือส่วนที่อยู่ระหว่าง `/d/` กับ `/edit`:
   ```
   https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/edit
                                          ^^^^^^^^^^^^^^^^^^^^^^^^^^^ <- อันนี้
   ```
   (ไม่ต้องสร้างแท็บ/หัวตารางเอง ระบบจะสร้าง 6 แท็บ พร้อมหัวตารางให้อัตโนมัติตอนรันครั้งแรก: `borrowers`, `equipment`, `records`, `requests`, `users`, `audit_log`)

### ขั้นตอนที่ 2: สร้าง Service Account (บัญชีสำหรับให้เซิร์ฟเวอร์เข้าถึงชีต)

1. ไปที่ [Google Cloud Console](https://console.cloud.google.com/) → สร้างโปรเจกต์ใหม่ (หรือใช้โปรเจกต์เดิม)
2. เปิดใช้งาน **Google Sheets API**: เมนู "APIs & Services" → "Enable APIs and Services" → ค้นหา "Google Sheets API" → กด Enable
3. สร้าง Service Account: "APIs & Services" → "Credentials" → "Create Credentials" → "Service account" → ตั้งชื่ออะไรก็ได้ → Create
4. เข้าไปที่ Service Account ที่สร้าง → แท็บ "Keys" → "Add Key" → "Create new key" → เลือก **JSON** → ระบบจะดาวน์โหลดไฟล์ `.json` มาให้ (เก็บไฟล์นี้ให้ดี **ห้ามแชร์ให้ใคร**)
5. เปิดไฟล์ JSON ที่ได้ จะเห็นค่า `client_email` (หน้าตาประมาณ `xxx@xxx.iam.gserviceaccount.com`) และ `private_key`

### ขั้นตอนที่ 3: แชร์ Google Sheet ให้ Service Account

กลับไปที่ Google Sheet ที่สร้างในขั้นตอนที่ 1 → กด "Share" (แชร์) → วาง `client_email` จากไฟล์ JSON ลงไป → ให้สิทธิ์ **Editor** → กด Send (ไม่ต้องติ๊กส่งอีเมลแจ้งเตือนก็ได้ เพราะเป็นบัญชีระบบ ไม่มีคนอ่าน)

### ขั้นตอนที่ 4: ตั้งค่าใน `.env`

เปิดไฟล์ `.env` (คัดลอกจาก `.env.example` ถ้ายังไม่มี) แล้วเติม:

```bash
GOOGLE_SHEET_ID=1AbCdEfGhIjKlMnOpQrStUvWxYz     # จากขั้นตอนที่ 1
GOOGLE_SERVICE_ACCOUNT_EMAIL=xxx@xxx.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n....\n-----END PRIVATE KEY-----\n"
```

ค่า `GOOGLE_PRIVATE_KEY` คัดลอกมาจากฟิลด์ `private_key` ในไฟล์ JSON ได้เลย (มี `\n` อยู่แล้วในไฟล์ ก็คัดลอกมาทั้งดุ้น ไม่ต้องแก้อะไร) อย่าลืมครอบด้วยเครื่องหมายคำพูดตามตัวอย่าง

ถ้าแพลตฟอร์ม deploy ที่ใช้ไม่รองรับ env var หลายบรรทัด/มี `\n` ให้ใช้ทางเลือก B แทน — วางเนื้อหาไฟล์ JSON **ทั้งไฟล์** เป็นค่าเดียวในบรรทัดเดียว:

```bash
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account","project_id":"...","private_key":"...","client_email":"...", ...}
```

(ตั้งค่านี้แทน `GOOGLE_SERVICE_ACCOUNT_EMAIL` + `GOOGLE_PRIVATE_KEY` สองตัวด้านบน ใช้อย่างใดอย่างหนึ่งพอ)

### ขั้นตอนที่ 5: รันระบบ

```bash
npm run seed   # ครั้งแรก: สร้างแท็บ + ผู้ใช้เริ่มต้น + อุปกรณ์ตัวอย่างลงใน Google Sheet
npm start
```

เปิด log ตอนสตาร์ทจะเห็นบรรทัด `โหมดจัดเก็บข้อมูล: Google Sheets` ยืนยันว่าเชื่อมต่อสำเร็จ ถ้าตั้งค่าไม่ครบ/ผิด ระบบจะไม่ crash เฉย ๆ แต่จะพิมพ์ข้อความบอกว่าค่าไหนขาดหรือผิดก่อนหยุดทำงาน

### ข้อควรรู้เมื่อใช้ Google Sheets เป็นฐานข้อมูล

- **ความเร็ว**: ทุกการอ่าน/เขียนเรียก Google Sheets API ผ่านอินเทอร์เน็ต จะช้ากว่าไฟล์ local เล็กน้อย (หลัก 100-500ms ต่อครั้ง) เหมาะกับปริมาณการใช้งานของหน่วยงานเดียว ไม่เหมาะกับ traffic สูงมาก (Google จำกัด quota ที่ 60 requests/นาที ต่อโปรเจกต์)
- **แก้ไขข้อมูลตรงในชีตได้**: พิมพ์แก้ในสเปรดชีตได้ตามปกติ (เช่น แก้จำนวนคงเหลือ) ระบบจะอ่านค่าล่าสุดทุกครั้งที่มีการเรียก API — แต่ **ห้ามแก้ชื่อคอลัมน์ในแถวหัวตาราง (แถวที่ 1)** เพราะระบบอ้างอิงชื่อคอลัมน์เหล่านี้ตรง ๆ
- **คีย์เข้ารหัสเลขบัตรประชาชน**: ต่อให้เปลี่ยนมาใช้ Google Sheets แล้ว คีย์เข้ารหัส AES (`ENCRYPTION_KEY`) ยังคงเป็นไฟล์ local (`data/.encryption_key`) เพราะเก็บใน Sheets ไม่ปลอดภัย — ถ้า deploy บนแพลตฟอร์มที่ดิสก์ไม่ persistent (เช่น serverless/container ที่รีเซ็ตทุกครั้ง deploy) **ต้องตั้งค่า `ENCRYPTION_KEY` เองใน .env ให้คงที่** ไม่งั้นข้อมูลเลขบัตรที่เข้ารหัสไว้เก่าจะถอดรหัสไม่ออกหลัง deploy ใหม่ (สร้างค่าแบบสุ่มได้ด้วย `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`)
- **รูปภาพยังอยู่ในเครื่อง server**: Google Sheets เก็บได้แค่ข้อมูลตัวอักษร/ตัวเลข ไฟล์รูปบัตรประชาชน/อาการป่วยยังคงเก็บในโฟลเดอร์ `uploads/` บนเครื่อง server เหมือนเดิม ต้องมี persistent disk สำหรับโฟลเดอร์นี้อยู่ดี
- **ย้ายกลับไปใช้ไฟล์ local**: ลบ/คอมเมนต์ `GOOGLE_SHEET_ID` ออกจาก `.env` (หรือตั้ง `STORAGE_BACKEND=local`) แล้วรันใหม่ — ระบบจะกลับไปอ่าน/เขียนไฟล์ JSON ใน `data/` ทันที (ข้อมูลจะไม่ sync ย้อนกลับจาก Sheets มาไฟล์ local ให้อัตโนมัติ ถ้าต้องการย้ายข้อมูลกลับต้องคัดลอกเอง)

## สิ่งที่ระบบทำ (ตามสเปกแต่ละโมดูล)

**4.1 ลงทะเบียนผู้ยืม** — ฟอร์มลงทะเบียน (ชื่อ, เลขบัตร ปชช., ที่อยู่, รูปอาการป่วย, คำอธิบาย) ตรวจสอบเลขบัตร 13 หลักด้วย checksum จริงของไทย บังคับแนบรูปบัตรประชาชนก่อนบันทึก บันทึก timestamp อัตโนมัติ เลขบัตรประชาชน**เข้ารหัส AES-256-GCM**ก่อนเก็บลงไฟล์ JSON (คีย์เข้ารหัสถูกสร้างอัตโนมัติที่ `data/.encryption_key` หรือกำหนดเองผ่าน `ENCRYPTION_KEY` ใน `.env`) หน้าจอทั่วไปแสดงเลขบัตรแบบ mask (เช่น `110xxxxxxx366`) ต้อง login ก่อนถึงจะเห็นเลขเต็มและรูปภาพ

**4.2 ยืม-คืนอุปกรณ์** — เลือกอุปกรณ์จากสต็อกจริง ผูกกับผู้ยืมที่ค้นหาได้ บันทึกวันที่ยืม/กำหนดคืน/สถานะ (ยืมอยู่ / คืนแล้ว / เกินกำหนด — คำนวณอัตโนมัติจากวันครบกำหนด) เมื่อคืนบันทึกวันที่คืนจริง สภาพอุปกรณ์ และผู้รับคืน ทุกการกระทำบันทึกผู้ทำรายการ (`handled_by` / `received_by`) และเขียนลง audit log

**4.3 คำขอยืม** — ฟอร์มสาธารณะที่ `/request.html` ไม่ต้อง login เข้าคิวสถานะ "รอดำเนินการ" เจ้าหน้าที่อนุมัติ/ปฏิเสธได้ในแท็บ "คำขอ" การอนุมัติจะสร้างรายการยืมจริงและตัดสต็อกทันที

**4.4 นับสต็อก** — แท็บ "สต็อก" แสดงจำนวนคงเหลือ/ถูกยืม/ทั้งหมดของทุกชิ้น อัปเดตอัตโนมัติทุกครั้งที่ยืม/คืน/อนุมัติคำขอ ขึ้นป้าย "สต็อกใกล้หมด" เมื่อจำนวนคงเหลือ ≤ threshold ที่ตั้งไว้ (แก้ไขได้)

**4.5 ประวัติ / Audit log** — แท็บ "ประวัติ" แยก 3 มุมมอง: ประวัติผู้ยืมรายคน (พร้อมสรุป % คืนตรงเวลา), ประวัติอุปกรณ์รายชิ้น, และ Audit log แสดงทุกการกระทำพร้อมชื่อเจ้าหน้าที่ที่ทำรายการ

## การตัดสินใจที่ทำไปแล้ว (ตอบหัวข้อ 6 ของสเปก)

ระบบนี้สร้างขึ้นตามที่ผู้ใช้เลือกไว้ตอนเริ่มพัฒนา หากต้องการเปลี่ยนภายหลังสามารถแก้โค้ดได้ตามจุดที่ระบุ:

1. **สิทธิ์ผู้ใช้**: 2 ระดับ — **แอดมิน** (จัดการอุปกรณ์/ผู้ใช้ + สิทธิ์ทุกอย่างของเจ้าหน้าที่) และ **เจ้าหน้าที่** (ลงทะเบียน, ยืม-คืน, อนุมัติคำขอ, ดูข้อมูลเต็มรวม PII) ผู้ยืมทั่วไปไม่มีบัญชี ส่งได้แค่คำขอผ่านฟอร์มสาธารณะ — ปรับได้ที่ `server/middleware/auth.js` และ `requireRole()` ในแต่ละ route
2. **การเข้ารหัส PII**: เข้ารหัสเลขบัตรประชาชนแบบ AES-256-GCM ที่ฝั่ง server ก่อนเขียนลงไฟล์ (`server/lib/crypto.js`) — รูปภาพ (บัตร ปชช./อาการป่วย) ยังเก็บเป็นไฟล์ธรรมดาในโฟลเดอร์ `uploads/` และเข้าถึงได้เฉพาะผู้ที่ login แล้วเท่านั้น (route `/uploads` มี `requireAuth`) — หากต้องการเข้ารหัสไฟล์รูปด้วย แจ้งเพิ่มได้
3. **PDPA**: ระบบเข้ารหัสเลขบัตร ปชช. และจำกัดการเข้าถึงข้อมูล/รูปภาพเฉพาะผู้ login แล้วตามที่สเปกแนะนำ แต่**ยังไม่ได้ทำ**เรื่อง data retention policy (ลบข้อมูลอัตโนมัติเมื่อพ้นระยะ), consent form, หรือ audit เต็มรูปแบบตามกฎหมาย PDPA — แนะนำให้ปรึกษาผู้เชี่ยวชาญด้านกฎหมายก่อนใช้งานจริงกับผู้ป่วย
4. **Deploy**: ระบบนี้เป็น Node.js app ธรรมดา รันได้ทุกที่ที่รองรับ Node (VPS ของตัวเอง, Railway, Render ฯลฯ) **ข้อควรระวัง (โหมดไฟล์ local)**: ข้อมูลเก็บเป็นไฟล์ JSON บน disk ของ server เครื่องเดียว จึงเหมาะกับการใช้งานจากเครื่อง/หน่วยงานเดียว ไม่รองรับ multi-server หรือ auto-scaling — ถ้าเปลี่ยนไปใช้ Google Sheets เป็นฐานข้อมูลแทน (ดู [เชื่อมต่อ Google Sheets](#เชื่อมต่อ-google-sheets)) ข้อจำกัดนี้จะลดลง เพราะข้อมูลไม่ได้อยู่บน disk ของเครื่องใดเครื่องหนึ่งอีกต่อไป แต่รูปภาพ (`uploads/`) และคีย์เข้ารหัส (`data/.encryption_key`) ยังต้องมี persistent disk อยู่ดี ไม่ว่าจะเลือกฐานข้อมูลแบบไหน

## การจัดการผู้ใช้ (เพิ่ม/เปลี่ยนรหัสผ่านเจ้าหน้าที่)

ยังไม่มีหน้าจอจัดการผู้ใช้ในเวอร์ชันนี้ (ไม่ได้ระบุไว้ชัดเจนในสเปก) เพิ่ม/แก้ไขผู้ใช้ได้ชั่วคราวโดยรันสคริปต์เล็ก ๆ เช่น:

```js
// add-user.js
require('dotenv').config();
const bcrypt = require('bcryptjs');
const { db } = require('./server/lib/db');
(async () => {
  const users = await db.read('users');
  users.push({
    user_id: db.nextId(users, 'U'),
    username: 'staff2',
    password_hash: bcrypt.hashSync('รหัสผ่านใหม่', 10),
    role: 'staff', // หรือ 'admin'
    name: 'ชื่อเจ้าหน้าที่',
    created_at: new Date().toISOString(),
  });
  await db.write('users', users);
  console.log('เพิ่มผู้ใช้แล้ว');
})();
```
รันด้วย `node add-user.js` — แจ้งได้หากต้องการหน้าจอจัดการผู้ใช้เต็มรูปแบบในเวอร์ชันถัดไป

## ข้อมูลสำรอง (Backup)

**โหมดไฟล์ local**: ข้อมูลทั้งหมดอยู่ในไฟล์ JSON ธรรมดา การสำรองข้อมูลทำได้ง่ายด้วยการคัดลอกทั้งโฟลเดอร์ `data/` และ `uploads/` ไปเก็บไว้ที่อื่นเป็นระยะ (เช่น cron job รายวัน) — แนะนำให้ตั้งการสำรองอัตโนมัติก่อนใช้งานจริง เพราะไม่มีระบบ replication เหมือนฐานข้อมูลจริง

**โหมด Google Sheets**: Google เก็บ version history ของสเปรดชีตให้อัตโนมัติอยู่แล้ว (กู้คืนเวอร์ชันก่อนหน้าได้จากเมนู File → Version history) แต่ยังแนะนำให้ตั้ง export อัตโนมัติเป็นระยะ (File → Download หรือใช้ Apps Script/Google Drive API ทำเป็น cron) เผื่อไฟล์ถูกลบทั้งไฟล์ — ส่วนโฟลเดอร์ `uploads/` (รูปภาพ) ยังต้อง backup แยกเหมือนโหมด local เพราะไม่ได้ถูกเก็บใน Google Sheets

## หมายเหตุความปลอดภัยเพิ่มเติมก่อนใช้งานจริง

- เปลี่ยนรหัสผ่าน `admin`/`staff` เริ่มต้นทันที
- ตั้งค่า `SESSION_SECRET` ใน `.env` เป็นค่าสุ่มที่ยาวและไม่ซ้ำใคร
- หากใช้งานผ่านอินเทอร์เน็ตจริง ต้องรันหลัง HTTPS (reverse proxy เช่น Caddy/Nginx) และตั้ง `NODE_ENV=production` กับ `TRUST_PROXY=1` เพื่อให้ cookie ปลอดภัยขึ้น
- ไฟล์ `data/.encryption_key` และ `.env` **ห้าม commit ขึ้น git หรือแชร์ให้ใคร** (มีอยู่ใน `.gitignore` แล้ว) — ถ้าใช้ Google Sheets ค่า `GOOGLE_PRIVATE_KEY`/`GOOGLE_SERVICE_ACCOUNT_JSON` ก็คือกุญแจเข้าถึงข้อมูลผู้ป่วยทั้งหมดเช่นกัน ห้ามหลุดออกไปเช่นเดียวกัน และไฟล์ service-account `.json` ที่ดาวน์โหลดจาก Google Cloud Console ก็ไม่ควร commit ขึ้น git เช่นกัน
